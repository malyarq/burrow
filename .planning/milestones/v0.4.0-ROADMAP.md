# Milestone v0.4.0: Launcher Truth And Product Polish

**Status:** ✅ SHIPPED 2026-04-17
**Phases:** 15-18
**Total Plans:** 16

## Overview

`v0.4.0` repaired the screenshot-backed trust defects left on FMCL's shipped launcher surfaces. The milestone focused on authoritative launch-state truth, correct modpack dependency semantics, catalog and compact-nav polish, settings-localization cleanup, and an explicit closeout proof chain that ended on a green packaging-aware gate.

## Phases

### Phase 15: Launch Truth And Shared Surface Contracts

**Goal:** FMCL's main play surface stops showing contradictory launcher state and missing-art failure modes by moving launch truth, progress, and localized runtime feedback onto one reliable shared contract.
**Depends on:** Phase 14
**Plans:** 4 plans

Plans:

- [x] 15-01: Make structured launch stage and progress authoritative
- [x] 15-02: Repair launch fallback art and loader summary truth
- [x] 15-03: Localize launch-adjacent controls and read-only busy-state behavior
- [x] 15-04: Close the launch surface on focused suites and dashboard proof

**Details:**
Phase 15 unified the classic dashboard around one truthful launch-state contract. It removed misleading `0%` progress, made the active loader summary match the real launch selection, reused the shipped launcher mark for missing artwork, localized launch-adjacent settings copy, and kept launch-affecting controls visible but read-only during active work.

### Phase 16: Modpack Detail Integrity And Discoverable Dense Navigation

**Goal:** Users can trust what modpack details say about runtime dependencies and reach primary detail sections without fighting dense-screen navigation.
**Depends on:** Phase 15
**Plans:** 4 plans

Plans:

- [x] 16-01: Resolve runtime dependency truth and readable requirement copy
- [x] 16-02: Replace hidden horizontal tabs with discoverable dense navigation
- [x] 16-03: Add a deterministic modpack-details manual proof seam
- [x] 16-04: Close Phase 16 with focused suites and a proof-friendly list fallback

**Details:**
Phase 16 fixed the modpack details surface so pack-provided runtime dependencies are recognized truthfully, incompatible runtimes are shown as mismatches instead of ordinary missing dependencies, requirement ranges render as readable product copy, and primary detail sections remain reachable without default horizontal-tab scrolling.

### Phase 17: Catalog, Compact Nav, And Settings Localization Polish

**Goal:** The remaining shipped-surface polish defects across catalog browsing, compact navigation, and settings localization are removed without reopening broader feature or IA redesign scope.
**Depends on:** Phase 16
**Plans:** 4 plans

Plans:

- [x] 17-01: Stabilize catalog controls and shared launcher-mark fallback imagery
- [x] 17-02: Make collapsed navigation read like an intentional compact shell
- [x] 17-03: Remove raw settings keys and localize preset naming
- [x] 17-04: Close Phase 17 on shared browser-backed proof

**Details:**
Phase 17 kept catalog controls readable at audited widths, replaced empty artwork placeholders with branded fallback imagery, made collapsed navigation state coherent without stray letters, and hardened the settings shell so Russian and English preset naming stays deliberate while raw localization keys no longer leak into the shipped UI.

### Phase 18: Verification And Release Truth

**Goal:** The milestone closes on proof, not assumption, by validating repaired surfaces through focused tests, manual walkthrough evidence, and truthful release-facing state.
**Depends on:** Phase 17
**Plans:** 4 plans

Plans:

- [x] 18-01: Lock the authoritative `v0.4.0` regression matrix
- [x] 18-02: Capture three-view browser-backed proof on the shared manual seam
- [x] 18-03: Refresh release-facing and planning-facing truth
- [x] 18-04: Pass the final packaging-aware gate and publish verification

**Details:**
Phase 18 consolidated the milestone around one proof chain: a focused automated matrix, browser-backed evidence for `dashboard`, `modpack-details`, and `phase-17-polish`, refreshed README and roadmap truth, and a green final gate on `npm test`, `npm run lint`, `npx tsc --noEmit`, and `npm run build -- --publish never`.

## Milestone Summary

**Decimal Phases:**

- None

**Key Decisions:**

- Reused shared seams such as `LazyImage` and `manual-verification.html` instead of introducing phase-specific fallback pipelines or browser harnesses.
- Treated structured launch state and installed modpack runtime data as the authoritative user-facing truth instead of allowing stale derived summaries to win.
- Kept closeout fallout limited to release-truth blockers, fixing only bounded `package.json` metadata debt at the final gate and carrying the large renderer chunk warning as explicit residual debt.
- Used the Phase 18 validation matrix as the authoritative requirement-to-seam map so milestone closure rested on owned proof instead of summary memory.

**Issues Resolved:**

- Contradictory launch progress, loader summaries, and missing-art behavior on the classic dashboard.
- False-negative runtime dependency states and raw requirement syntax on modpack details.
- Catalog fallback-art and compact-navigation coherence defects on audited desktop surfaces.
- Raw settings localization keys and inconsistent RU/EN appearance preset naming.

**Issues Deferred:**

- No standalone `v0.4.0-MILESTONE-AUDIT.md` was recorded before archive; closeout relied on Phase 18 verification artifacts plus green repo/build gates.
- The Vite large-renderer-chunk warning remains non-blocking and should be evaluated during next-milestone planning instead of being forced into this polish release.

**Technical Debt Incurred:**

- No new product-surface debt was introduced during closeout; the only carried debt is the pre-existing renderer chunk split work intentionally left outside milestone scope.
